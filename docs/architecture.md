# 架构说明

> 本文描述 MemWeave 当前公开的产品与运行时边界。内部阶段、证据和未公开计划不在这里维护。

## 一句话

MemWeave 是一个常驻 stdio MCP，为已有编程 Agent 提供**任务工作记忆**和**有范围、有来源的长期知识**；它不替代宿主，也不启动自己的模型。

## 两层产品语义

### 任务工作记忆

同一项目只推进一个主 `current` 任务，其余主任务按确定顺序排队；任务内部可以使用多个 WorkUnit 并行。

任务工作记忆包括：

- 目标与验收条件；
- 约束、决策、发现、失败尝试和验证结果；
- 当前进展和唯一下一步；
- 并行 WorkUnit 的负责人、范围、状态、发现、失败和下一步；
- 阶段边界和任务关闭时的验收结果。

任务状态落在本机 Markdown；SQLite 只是可重建的派生索引。关闭任务不会自动把任务正文变成长期知识。

### 长期知识

长期知识只来自任务或阶段的真实证据，并按范围隔离：

| scope | 适用对象 |
|---|---|
| `project` | 同一项目的后续任务和新会话 |
| `group` | 父项目显式汇总的组知识，成员项目按需检索 |
| `user` | 用户明确要求长期保留的偏好或规则 |

每条知识带来源、状态（candidate / active / retired）和修订记录。候选知识不进入默认上下文；显式审查并激活后才参与召回。项目事实不能为了跨项目复用而写成用户范围。

文件结构和架构关系是核对记忆是否仍适用于当前代码的支撑证据，不是第三层记忆。

## 运行时组成

```text
宿主 Agent
   │  MCP stdio
MemWeave MCP
   ├─ 项目身份（绝对文件夹）
   ├─ 任务 / 检查点 / WorkUnit / phase
   ├─ 长期知识（project / group / user）
   ├─ Markdown 权威记录
   └─ SQLite FTS 派生索引
```

产品保持一个 MCP、一个 Skill 和一个会话启动通道。Skill 规定工作循环；启动通道负责在首轮要求 `workspace_prepare`。宿主支持时启动通道由低频 Hook 实现，否则使用 always-on Rule 或等价首轮指令。

## 恢复契约

完整接入要求模型在第一次项目动作调用：

```text
memweave_system_status
memweave_workspace_prepare(root=<绝对执行根>, intent=inspect|new|resume)
```

`inspect` 只读；继续工作才使用 `resume`，由当前 MCP 服务实例取得执行权。另一个活实例继续同一任务时会得到 `task_claimed`，不能同时推进主任务。

`workspace_prepare` 之后应核对当前用户目标、任务检查点和实际文件/测试；如果保存的 `next_step` 与当前代码矛盾，先更新检查点，不要重放过期步骤。

没有启动块、Hook 未送达或压缩/重连后，不应假设没有任务，也不要等待 Hook：直接走同一恢复入口并核对实际文件。

## 写入与并发

- 所有变更带唯一 `operation_id`；重试同一请求使用同一个 ID。
- 任务和知识更新使用 revision/etag，冲突时保留现场，不静默覆盖。
- WorkUnit 的独立 revision/etag 只保护记录并发，不隔离文件系统；并行改代码仍需独立 worktree 或互不重叠的文件范围。
- 受管安装器修改客户端配置时保留已有内容，写入前备份，冲突时停止并报告。

## 项目身份

项目身份是绝对文件夹，不是客户端。同一文件夹由 Codex、Cursor、Devin 或其他 MCP 客户端打开时，复用同一个项目、任务队列和知识。

- 显式登记的子文件夹是独立项目；
- 未登记子目录归最近的已登记父项目；
- 同一 Git common directory 的 linked worktree 是主 checkout 的执行别名，不产生第二个项目；
- 不同 clone 分别登记。

父项目可以只读汇总直接子项目的 `current` 摘要和知识概况，但不接管子项目任务。组知识写在父项目；子项目默认不注入，只有显式检索才返回。子项目恢复只读自己，不读取父项目任务。

## 存储与检索

- Markdown 是任务和知识的权威记录；
- SQLite FTS5 是派生索引，可重建；
- 当前不使用向量检索；
- 知识召回按项目、范围和状态过滤，并受上下文预算约束；
- 记录 ID 不是远程访问凭证。

## 安全边界

MemWeave 当前面向可信的本机单用户：

- 不保存凭据、完整 transcript 或大段工具输出；
- 外部知识、文件和 Hook 注入内容都按不可信参考数据处理；
- 安装检查、协议探针和桌面真实加载是不同证据，不能互相替代；
- 任务验收由宿主报告，不由 MemWeave 自行推断“已完成”。

## 客户端适配

所有客户端共享同一个 22 工具核心、任务/知识模型、项目身份和恢复契约。客户端差异只影响：

- 配置位置和资源格式；
- Skill/Rule 的安装方式；
- 启动通道：生命周期 Hook、always-on Rule 或手工首轮指令；
- 压缩快照能力；
- 真实桌面验证的证据成熟度。

这些差异不是核心能力分级。只连接 MCP 而没有启动通道时，状态应标记为“核心已连接，尚未完整接入”。

具体安装和验证见 [客户端接入](integrations.md) 与 [Agent 安装入口](../AGENT_INSTALL.md)。
