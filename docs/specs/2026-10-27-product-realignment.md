# 织忆目标与本轮修正基准

> 状态：这是 **0.2.5 融合前行为的历史基准**，用于迁移和历史对照。Phase 1 已替换其存储搜索后端并接入 Basic Memory；任务生命周期与 Hook 行为仍大体沿用。目标见 [AGPL 深度融合目标规格](2026-10-27-agpl-fusion-target.md)，执行顺序见 [PLAN.md](../../PLAN.md)。

日期：2026-10-27。依据：产品文档 v0.1、原讨论，以及用户明确的“不需要独立客户端”“先对齐目标，然后修正”。原始文档保留。

## 产品目标

织忆为已有编程 Agent 提供持续的任务记忆、项目理解与合作积累：

1. 任务工作记忆保存目标、约束、计划进展、发现、失败尝试与验证，减少遗忘、偏离和重复探索。
2. 长期记忆积累有范围、来源和适用条件的项目知识与用户明确偏好，减少重复交代和纠正。
3. 文件结构与项目架构两层图谱连接任务、实现、决策和验证，帮助定位，并核对历史理解是否仍适用。

跨会话、跨工具接续是上述能力的使用场景。首批客户端仍为 Codex 桌面版与 Cursor，采用 MCP + Skills + Hooks。Python、Markdown + SQLite、宿主负责理解和提炼的选择不变。本地管理页按需辅助查看、纠正与遗忘，日常工作不要求打开页面。

## 四个时点的默认行为

| 时点 | 期望行为 | 用户需要参与的情形 |
|---|---|---|
| 开始或恢复 | 识别明确的工作目录和任务，取回相关记忆、局部结构与当前变化提示 | 多个任务无法确定归属、要使用用户范围知识 |
| 执行 | 宿主在重要发现、失败、阶段变化和验证后保存检查点；按需查证和更新架构理解 | 影响行动的冲突或权限问题 |
| 阶段结束或完成 | 宿主核对验收，提炼、去重、修订知识；不确定内容保留候选 | 重要推断的确认、超出原授权范围的保存 |
| 下一次相关工作 | 按范围和问题取回经验与结构，尊重纠正、遗忘和代码变化 | 历史知识与当前要求存在影响行动的歧义 |

Hooks 仅在宿主真实支持并验证的事件上补充自动化；缺少事件时走明确的主动 MCP/Skill 路径。事件收据不等于已恢复、已保存检查点或已完成提炼。

## 本轮实现范围

本轮修正已有入口与上下文组合，不引入新技术栈，不扩大采集范围，不修改用户全局客户端设置。

- README 与接入指引以 Agent 内工作流程为主；准确区分工程可用与产品体验未验收。
- 新增只读 `workspace_prepare(root, intent="inspect", task_id=None, query="", include_user=False, budget=12000)`，CLI 与 MCP 共用。
- root 必须是存在的绝对目录，精确匹配已注册根目录；不自动合并子目录、克隆或 worktree。
- intent 为 inspect/new/resume。inspect 列出任务但不选择；new 不恢复已有任务；resume 仅在显式指定任务或只有一个活跃任务时选择。多个活跃任务保持 task_selection_required，无任务上下文，不按最近时间猜测。
- 未注册时返回 registration_required，不偷偷创建项目或任务。任务选择列表最多 20 项并标记截断；待提炼任务单独列出。
- `context_get` 在总字符预算内组合当前任务摘要、已启用知识与有效局部图谱，避免长历史挤掉后两类信息。任务摘要优先显示最新下一步。
- 返回实际纳入的来源标识和截断状态；图谱返回覆盖与新鲜度摘要。来源变化后的架构不进入有效上下文，新文件仍需重扫。用户知识保留显式 opt-in。
- 更新原创接续 Skill，明确四时点和新入口；保留已有写入与冲突协议。

## 验收与声明边界

本轮工程验收：工作目录匹配、任务歧义隔离、new 不恢复旧任务、无隐式写入、用户范围选择、长历史下知识/结构仍可进入、图谱漂移排除、预算与来源标识、真实 MCP 服务重启后恢复。

后续产品验收：在真实 Codex 桌面版与 Cursor 中，观察持续记录、任务恢复、经验提炼、下次主动使用、用户纠正生效；同 IDE 也应受益。记录客户端版本、调用证据及使用负担。对照无记忆、仅任务记忆、完整记忆与图谱，评价遗漏、重复探索、重复说明、纠正成本和额外开销。

协议测试、页面演示和指引更新不能代替这些产品验收。未完成公平模型对照时，Skill 仅报告工程/冒烟观察，不宣称自动触发或收益改善。
